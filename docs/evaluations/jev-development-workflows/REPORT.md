# Jev in six development workflows — live, bounded evaluation

**Result (2026-09-23): Jev made 15 real, successful `jev-1.13.0` calls across all six use cases.** It showed a concrete component-level gain in feedback history retrieval; broader completed-work savings remain unmeasured. Twelve calls used frozen initial/perturbation packets, two were focused corrections, and one tested the full live feedback candidate pool. The calls used 54,246 input and 3,097 output tokens, with $0.002278332 of locally calculated API cost and 4.628 seconds summed HTTP time. The complete [typed responses and per-call receipts](live-results-v1.json), [frozen first packets](live-packets-v1.json), [first reference outcomes](live-reference-v1.json), [correction packets](live-packets-v2.json), and [correction reference](live-reference-v2.json) are retained. TypeSafe's [current model contract](https://docs.typesafe.ai/models) prices input at $0.042 per million tokens, output free, with a 64k-token request limit. Account balance and subscription usage were not exposed. No Neri pilot dispatch was used: its ledger remained at 242 rows, $0.071314950 spent, and $0.005376 reserved before and after.

The previous [baseline-only results](results-v1.json) established local workflows and integration risks but **did not test Jev**; their no-Jev recommendations are superseded by this report. A live model choice is evidence of a judgment, not evidence that completed work improved. The first-pass budget classification disagreement is also not a clean Jev failure: our packet omitted the called transport body, and our first rubric overlapped “partial” with “contradicted.” Astra independently found both defects. The correction added complete relevant code and disjoint counterexample precedence; Jev then selected `contradicted`. This is a corrected repeat, not fresh validation.

The agent-controlled input risk is real. The live Neri endpoint's dry run accepted a nonexistent source ID and worker-authored source/rubric hashes without resolving them. For these local calls, [the preparation script](prepare_live_jev.py) assembled source text and whole-file hashes before inference, [the runner](run_live_jev.py) rechecked those hashes and model windows, and the reference answers were committed before the calls. The [full-pool script](prepare_history_pool_trial.py) fetched every active same-component/type feedback record across projects, checked count and row hashes, and froze an independent [Astra reference](history-pool-reference-v1.json) before Jev inference. That still does not prove general accuracy or packet completeness—the first claim packet's omitted transport body was caught only by review. The cases are frozen, but not a new blind held-out cohort. A source-instruction fixture, persuasive narration, skill order/description changes, and a leading routing summary did not change the tested decisions; the order swap changed search position as expected. Exact receipt replay created zero new provider calls; changed evidence/rubric used new IDs and two new calls. Mocked timeout, unavailable-model, and malformed-response probes remained `not_evaluated`; all live provider calls succeeded, so live outage handling is untested. The runner supplied a bounded HTTP client because the reusable provider helper defaults to `timeout=None`, and it never retries an uncertain call.

Calling without `--validate-only` on an existing ID reuses its receipt, not the provider. [The summarizer](summarize_live_jev.py) regenerates the compact results. No production rebuild, deployment or publication occurred.

The opportunity ranking supported by these packets is (1) advisory feedback history matching, where the full-pool trial found a real lexical miss, (2) targeted reranking on an actual noisy search, and (3) claim triage with complete authoritative evidence. Skill discovery, workflow scoring, and model routing remain less differentiated here. Astra's independent audit found that several chosen tasks were already easy for the baseline, and the repeated-concern worker counts are not comparable enough to infer an efficiency loss. The current `duplicate_candidates` list is an unsafe destination for semantic leads because `create_feedback` can auto-vote its first entry; keep Jev's verified links in a **separate advisory history section**.

**Single best next action: use Jev as an opt-in advisory history selector at feedback handoff, with all active same-component/type records assembled from authoritative storage and verified links shown separately from voting.** Compare it prospectively on unseen concerns before enabling a shared default; measure relevant-history recall, false links, source reads, total time and usage.
