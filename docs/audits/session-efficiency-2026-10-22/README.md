# Session efficiency view and routine

This isolated checkpoint adds a session-first review to the existing Activity panel and a pinned-window read query. Sessions rank by measured admin/support seconds, independently of provider-token rank or task bindings. Open a session row for substantive/admin/unknown tool occupancy, duration and returned-text coverage, recorded provider usage, sampled event span, repeated admin families and its existing session link. Existing accounting, ST estimates and task read-side data are preserved. No per-task producer, schema/store, ST invocation work, network capture, mandatory form or global prompt edit was added.

The coordinator's scope updates replace the initially considered admin-share threshold. The proposed **local-trial goal is at least 20% lower full API-equivalent cost per accepted outcome, with acceptance criteria and checks unchanged**. This is a conditional experiment target, not a typical-overhead benchmark or a measured result. The coordinator owns the matched Pi/Codex/Hub trials, with/without injected context, and the primary research report. The panel explicitly says the trials are pending and does not assess that cost goal from admin share. The admin-share target remains **unset**, in the owning `activity_policy.json`. The trial reduction target is also configuration there.

If an admin-share target is later selected, existing measured non-wait tool occupancy is its denominator; admin includes necessary support. The policy's 80% duration-call coverage and 20% maximum unknown-time share are local review flags, not research-calibrated confidence bounds. Capped, unmeasured and limited samples stay explicit before goal selection. Even passing these flags cannot bound missing time or prove whole-session efficiency. Repetition and admin classification do not establish avoidability. Substantive tool work is only a productive-work signal; acceptance and useful results need their existing evidence.

Use the existing admin auth on `GET /api/admin/session-efficiency`. Parameters: `hours` (1–168), `limit` (1–20), timezone-aware `until` (exclusive end, no future time), and optional exact `project_id`, `provider`, `model`, `session_id`. Filters apply to events, accounting and session selection **before** the event cap. No inferred task or command-argument association is used. `model` is the stored session model; it may be unknown or change and does not establish each served model.

For example, compare these adjacent one-hour windows, then add `session_id` for a particular row:

```text
/api/admin/session-efficiency?hours=1&until=2026-10-22T17%3A53%3A00Z&project_id=agent-hub&provider=codex&limit=20
/api/admin/session-efficiency?hours=1&until=2026-10-22T16%3A53%3A00Z&project_id=agent-hub&provider=codex&limit=20
```

The method identifier is `session-tool-occupancy-v1`. Window bounds are `[start,end)` for events and ledgers, so a boundary record is not counted in both adjacent windows. Pinning time does not freeze the retained dataset: late ingestion or repair can change a later read. Narrow capped windows or filter a session before comparing; shown/total session and family counts expose ranking limits. Keep project/provider/stored-model and work type comparable. Unknown model identity is a comparison limit, not evidence of a match. Changed tools/policy/ingestion can change coverage and classification; retain their source revision with any comparison.

The lean routine appears in a native disclosure, with no mandatory reporting:

1. At the start, inspect one comparable window and its coverage; pick the largest repeated admin family.
2. Read that session once. Preserve necessary checks and coordination; simplify one demonstrated repeat, such as checks rerun against unchanged source or repeated context discovery.
3. At the end, compare equal windows with the same filters/method. Keep substantive work, unknowns and coverage visible. A smaller admin share alone does not prove progress.
4. Leave the result, session link and one next change in the existing work record or handoff. Use the separate matched-trial evidence for acceptance, quality and the proposed cost goal.

Accounting retains its existing one-source precedence and disjoint cache partitions. Provider token totals measure repeated provider input/output, not unique history text. The per-session character footprint estimates sampled arguments plus retained returned text; it is neither billed tokens nor resident working context. Tool intervals are unioned within a session; concurrent sessions add agent-time. Explicit wait-only intervals are excluded. Sampled event span measures elapsed first-to-last retained tool/usage observation, including gaps; it is not full session elapsed time, thinking or idle time. Missing duration, unretained/truncated output, incomplete ingestion and ambiguous wrappers remain unquantified. No causal admin token allocation or avoidable-waste total is invented.
